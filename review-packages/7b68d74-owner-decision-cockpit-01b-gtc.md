## What changed

Implements exactly the design proposed and accepted in the audit
(section 5), with one small addition reality required (see "Deviation
from the audit's prediction" below).

- **`ops/gtc_plan_contract.py`** (new): `GTC_PLAN_SCHEMA` (Rank,
  Ticker, Matrix Tier, Stage, Kind of Play, Current Ref, Buy/Sell GTC
  Range Low/High, Mode, Simple Rule — exactly the audit's proposed
  schema). `to_gtc_plan_row()` is raw passthrough, importing and
  reusing `mobile_contract.py`'s own `_value_or_unknown()`/
  `_zone_or_none()` helpers directly (not reimplemented). `build_gtc_plan()`
  sorts by `Rank` ascending — the **one** place across all four mobile
  contracts sorting is authorized, since the Daily GTC Plan tab's own
  canon defines `Rank` as its ordering field (every other contract
  still never sorts). Fails closed with a new `AmbiguousGtcRankError`
  if any row's `Rank` is missing, non-numeric, or a boolean (bool is
  an `int` subclass in Python — explicitly rejected, not silently
  accepted as rank 0/1) — checked for every row up front, mirroring
  `build_mobile_snapshot()`'s existing "surface every problem row at
  once" pattern.
- **`ops/gtc_plan_export.py`** (new): a separate CLI
  (`python3 -m ops.gtc_plan_export --input <path> --output
  pwa/private-data`) mirroring `mobile_snapshot_export.py`'s structure
  exactly — same `utf-8-sig` BOM handling, a new `validate_gtc_schema()`
  scoped to `GTC_PLAN_SCHEMA` (raises the same `SchemaViolation` type,
  since `niklar_stocks_ops_v4.py`'s own `validate_schema()` is
  hardcoded to `FROZEN_SCHEMA` and stays untouched), reuses
  `niklar_stocks_ops_v4.schema_hash()` unchanged (it was already
  header-list-generic) and `mobile_snapshot_export._verify_output_path_safe_to_write()`
  directly (imported, not duplicated) for the same git-ignore safety
  net. Writes a single flat `gtc-plan.json` array — same shape as
  `opportunity.json`/`watchlist.json`/`tactical.json` — into the same
  output directory the existing exporter uses, confirmed (by test) not
  to touch or be touched by that exporter's own four files.
- **`pwa/index.html`/`app.js`/`styles.css`**: new Daily GTC Plan
  section, placed near the top (right before Opportunity Landscape,
  after the Invalidation Unknown highlight) per the audit's "prominent
  near the top" requirement. Renders in exactly the order the fetched
  array arrives in — `build_gtc_plan()` already Rank-sorted it
  server-side, so `renderGtcPlanRow()` does no ordering work, same
  never-sort-in-the-client discipline as every other row renderer.
  Cross-navigation extended: a GTC Plan row jumps to its matching
  Quick Review card via the exact same `jumpToTacticalCard()`
  mechanism already used for Opportunity rows — one more caller, no
  new lookup logic. The existing global ticker search covers GTC Plan
  rows with **zero new search code**, since `applySearchFilter()`
  already operates on every `[data-ticker]` node document-wide.
- **`pwa/service-worker.js`**: added the new DEMO fixture filename
  (`gtc-plan-data.json`) to the never-cache `DATA_ENDPOINTS` list.
  `private-data/gtc-plan.json` needed no change — already covered by
  the existing `url.pathname.includes("/private-data/")` check, as
  the audit predicted and this batch's tests then confirmed in
  practice.
- **`pwa/gtc-plan-data.json`** (new DEMO fixture): generated by
  actually running `build_gtc_plan()` against synthetic
  `DEMO1`/`DEMO2`/`DEMO4` rows supplied in deliberately non-Rank-sorted
  input order (Rank 3, 1, 2) — proving in the fixture itself, not just
  by assertion, that the client renders what the server already
  sorted.

## Deviation from the audit's prediction (disclosed, not silent)

Section 6 of the audit predicted `service-worker.js` would need **zero**
code change. That held for the `private-data/gtc-plan.json` path (the
existing substring check already covers it), but the audit didn't
separately consider the new **DEMO fixture's root-level filename**
(`gtc-plan-data.json`, alongside `sample-data.json`/
`opportunity-data.json`/`watchlist-data.json`) — those are matched by
an explicit filename list, not a path-substring check, so the new
fixture needed one line added to `DATA_ENDPOINTS`. A one-line,
narrowly-scoped addition, not a design change — flagged here rather
than silently absorbed into "as predicted."

## Explicitly NOT done (per the sub-batch's own boundary)

No numeric type coercion beyond what CSV/JSON naturally gives (Buy/Sell
GTC Range values pass through exactly as the source format supplies
them). No per-GTC-file `meta.json`/timestamp manifest — the existing
top-level `meta.json`'s `generated_at` already governs the whole app's
PRIVATE SNAPSHOT banner, and none of the other three sections have a
per-section timestamp either, so adding one only for GTC would be an
inconsistent, un-asked-for addition. No `data_completeness`/
`missing_core_fields` field on the GTC contract — `GTC_PLAN_SCHEMA`
doesn't define a completeness concept and this contract computes
nothing beyond raw passthrough, so inventing one would be scope
creep beyond the accepted design. `ops/niklar_stocks_ops_v4.py` and
`ops/mobile_contract.py`: zero changes, confirmed via diff.

## Self-audit against the standing 4 criteria

1. **Failure envelope**: fails closed at every named point — GTC
   schema mismatch (`SchemaViolation`), unusable `Rank`
   (`AmbiguousGtcRankError`, checked for every row before any
   transform), unsupported file extension
   (`UnsupportedGtcSnapshotFormat`). The PWA's per-section loading/
   error/empty state machine (`initSection()`) is reused completely
   unchanged for the new section — no new failure path invented, no
   weakening anywhere else (confirmed via the full regression suite).
2. **Unnecessary abstraction/dependency**: none. Every new piece
   reuses an existing pattern directly — `_value_or_unknown()`/
   `_zone_or_none()` (imported, not reimplemented), `schema_hash()`
   (imported, unchanged), `_verify_output_path_safe_to_write()`
   (imported, not duplicated), `initSection()`/`applySearchFilter()`/
   `jumpToTacticalCard()` (extended with one more caller, not forked).
   No new JS/CSS framework, no new Python dependency.
3. **Security/privacy**: no new network surface beyond one more static
   JSON file served from the same origin under the same
   `Cache-Control: no-store` (via `serve.py`, unchanged) and
   service-worker exclusion protections already proven for
   `private-data/`. No client-side storage (`localStorage`/
   `sessionStorage`/`indexedDB`/`document.cookie`: zero matches in this
   diff). No credential handling anywhere in the new export tool.
4. **Canonical boundary drift**: `ops/niklar_stocks_ops_v4.py` and
   `ops/mobile_contract.py` — zero changes, confirmed via `git diff`
   against both paths returning nothing. The Daily GTC Plan is treated
   as a genuinely separate canonical artifact throughout — its own
   schema, its own hash, its own export tool, its own contract module
   — never folded into or substituted for `FROZEN_SCHEMA`/
   `Current Reference`.
