FINDING (gemini_client.py, missing failure-envelope coverage):
diagnose()'s try/except around the Gemini HTTP call handled
urllib.error.HTTPError / URLError / TimeoutError -- all three cover
failures during connection *setup*. A connection that succeeds and is
then reset, or returns an incomplete body, *while streaming the
response* was uncaught:
  - ConnectionResetError (an OSError subclass, but not a URLError one)
  - http.client.IncompleteRead (not even an OSError subclass)
run.py's main() only ever catches GeminiError from diagnose(). An
uncaught exception of either kind above would propagate straight past
gemini_client.py, crash the whole worker process, and lose the
deterministic FAIL report the run had already earned before Gemini was
even invoked -- directly contradicting the module's own documented
"never an unhandled traceback" guarantee (its docstring's own words).
Found by reading the code, not by a live failure.

FIX: added `except (OSError, http.client.HTTPException) as exc:
raise GeminiError(...) from None` after the three existing clauses --
same graceful-degrade-to-GeminiError path as every other Gemini-side
failure mode already handled there (HTTP error, unreachable, timeout,
blockReason, MAX_TOKENS, zero candidates, non-JSON body, missing
field). No new behavior class introduced.

TEST COVERAGE GAP ALSO CLOSED: gemini_client.py -- the module with the
most branching error-handling in this package -- had ZERO automated
tests before this commit, only ad-hoc manual verification against the
real endpoint (documented in its own README). That is exactly how a
bug like the one above stays invisible. Added
tests/test_ai_qa_gemini_client.py: 14 tests, fully mocked (no real
network call), covering:
  - happy path (valid structured diagnosis round-trips correctly;
    optional affected_files field defaults to empty list)
  - every network-failure mode: HTTPError (+ secret redaction of the
    error body verified), URLError, TimeoutError, and 2 regression
    tests for this exact finding (ConnectionResetError and
    IncompleteRead -- both needed, since only one is an OSError
    subclass)
  - every malformed-response shape the code already handled:
    blockReason, MAX_TOKENS, zero candidates, non-JSON top-level body,
    non-JSON structured text, missing required field

OTHER 4 MODULES: reviewed against the same 6 criteria. No findings.
redact.py/failure_extract.py/run.py/config.py are unchanged by this
