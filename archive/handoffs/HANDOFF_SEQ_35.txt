`PWA-BFCACHE-NO-STORE-HARDENING-01` (Drive sync doc RESPONSE_SEQ 31,

MATERIAL_DELTA: The documented local server sent no `Cache-Control`
header on any response, including the HTML app shell — a browser's
back-forward cache (bfcache) could restore an already-rendered page
(real trading data included) via the Back button without a network
request. Real, domain-independent gap, unrelated to whether/when
Cloudflare remote access is ever added.

New `pwa/serve.py`: a minimal wrapper around the exact same stdlib
`SimpleHTTPRequestHandler`/`HTTPServer` pattern already used elsewhere
in this repo (no new framework/dependency). `NoStoreHTMLRequestHandler`
hooks `send_header()` to catch the base class's own `Content-Type:
text/html` signal (robust to both a direct `/index.html` request and
the indirect `/` → `index.html` directory-resolution path) and adds
`Cache-Control: no-store` only to that response.

Non-HTML assets, `app.js`'s existing private-data `{cache: "no-store"}`
fetch behavior, `service-worker.js`'s network-only `/private-data/`
handling, DEMO/PRIVATE mode resolution, the 63-column contract, and
all trading/scoring/tactical/Decision Object logic are all unaffected
— confirmed via the unchanged regression suite and by leaving
`mobile_contract.py`/`niklar_stocks_ops_v4.py` (both Drive-verbatim)
untouched.

`pwa/smoke_test.py` now serves via the same handler real owner usage
does (not a parallel implementation that could drift out of sync),
with a new assertion that `index.html` gets the header and every
other asset does not. `pwa/README.md`'s "Running it locally"/LAN-mode
sections updated to the new `python3 serve.py` command, same
`--port`/`--bind` names and defaults as the command it replaces.

Manually verified against the real documented command: `curl`
confirmed `Cache-Control: no-store` on both `/index.html` and `/`,
confirmed absent on `/app.js`, confirmed the existing DEMO fallback
(`private-data/meta.json` 404 when no snapshot exists) unaffected.

Known, accepted limitation documented in `serve.py`'s own docstring: a
`304 Not Modified` response doesn't carry the header (self-resolving
once a client receives `no-store` on a fresh `200` response) — not
fixed further, per Minimum Sufficient Code.
