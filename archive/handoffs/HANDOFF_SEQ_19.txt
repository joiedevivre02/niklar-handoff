New file `ops/niklar_notification_service.py`, four pieces, each a
**direct implementation of Section 19's own text**:
- `derive_notification_id()` — deterministic id from exactly the
  stable fields Section 19 names (run/checkpoint/channel/scope/
  Decision Object version), via sha256, same determinism convention as
  `niklar_stocks_ops_v4.schema_hash()`.
- `check_duplicate_send()` — the DUPLICATE/RESEND gate: a prior
  successful send for the same id requires an explicit resend action;
  a prior failed attempt does not block a fresh one.
- `decide_notification_eligibility()` — the STALE/CAVEAT GATE: reuses
  Batch 1's `EVIDENCE_COMPLETE`/`CONDITIONAL`/`INSUFFICIENT` contract
  directly rather than inventing a parallel evidence-quality concept;
  `execution_sensitive` and staleness thresholds are caller-supplied,
  not guessed at (this repo has no synced definition of which
  conclusions count as execution-sensitive).
- `classify_delivery_attempt()` — the DELIVERY STATUS classification
  against a real retry budget.

**Preview content deliberately NOT reimplemented** — Section 19's
"show exactly what Slack will receive" is already satisfied by the
existing `render_preopen`/`render_intraday`/`render_near_close`
renderers; wrapping them would duplicate, not implement, anything.
The actual Slack HTTP delivery, PWA UI wiring, and consolidated-brief
ticker-eligibility selection remain separate, explicitly out of scope.
