MATERIAL_DELTA: One real, narrow bug found and fixed. The owner's real
export — saved as "UTF-8" by a spreadsheet tool — carried a leading
byte-order mark (BOM). `load_snapshot_rows()` read files with plain
`"utf-8"`, so the BOM surfaced as a literal `U+FEFF` character
prepended to the text, corrupting the first column name (`Ticker` →
`﻿Ticker`) and failing schema validation for a reason unrelated to
the actual data. Fixed with `encoding="utf-8-sig"` instead — strips a
leading BOM if present, exactly equivalent to `"utf-8"` if one is
absent, fully backward compatible. Applies uniformly to both the CSV
and JSON read paths.

Distinguished this from the "never guess" discipline governing field
semantics (the prior F1 fix): BOM handling is a well-defined,
mechanical text-**decoding** convention ("how are these bytes turned
into text"), not a business-**semantics** guess ("what does this value
mean") — so fixing it does not conflict with that discipline.
`AmbiguousFieldTypeError`'s fail-closed behavior for genuinely
ambiguous field values is completely unaffected, confirmed by the full
regression suite (including every pre-existing
`SchemaViolation`/`AmbiguousFieldTypeError` test) still passing.
